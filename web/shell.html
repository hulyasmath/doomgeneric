INCORPORATE IT INTO ANOTHER GAME OR SIMULATION

  1. Baseline the real host. Identify its authoritative tick, complete command input, one-step transition, and every future-affecting state field. Run a fixed scenario twice before changing mechanics.
  2. Adopt exact time first. Compile zeq_time.c or load the JavaScript runtime with its generated table. Pass shared vectors, including overflow and negative cases. Keep it observational until replay is stable.
  3. Version the run. Bind source, content, settings, ruleset, tick rate, and initial state. Capture complete commands—not raw key events—and compare canonical hashes in an actual rerun.
  4. Opt into more only as needed. Define host units before using physics; keep Vanilla as a separate ruleset; add saves, evidence, content, or networking behind explicit profiles and capability gates.
